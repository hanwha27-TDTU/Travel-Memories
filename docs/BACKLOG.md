# BACKLOG · Bugeon Journey — 미완료 과제 단일 정본(SSOT)

> 🔴 **미완료 과제의 상태는 이 파일 한 곳에만 산다.** 다른 문서(ROADMAP·HANDOFF·ASSUMPTIONS 등)는
> 과제를 언급할 때 **T-번호로 링크만** 하고 상태를 다시 적지 않는다 — 두 곳에 적힌 상태는
> 반드시 갈라진다(ROADMAP이 실제로 그렇게 낡았다 · 2026-08-03 교차검증, HANDOFF-0057).
>
> **왜 이 문서는 같은 운명(낡음)을 피하는가** — 조항이 아니라 구조로(§7 3층):
> ① 이 조항 ② `npm run brief`가 **모든 착수 브리핑에 열린 과제를 자동으로 띄운다**(안 읽고는
> 일을 시작할 수 없다) ③ `check-doc-governance`가 문서 지도 등록을 강제한다.
>
> **규칙**
> - 과제를 끝낸 커밋이 **같은 커밋에서** 그 행을 「완료 아카이브」로 옮긴다(나중에 옮기는 것은 없다).
> - 검증 증거(PR·HANDOFF 번호·read-back) 없이 완료로 옮기지 않는다(정직한 완료).
> - 새 미완료가 생기면(작업 중 발견 포함) 같은 커밋에서 행을 추가한다.
> - 상태 값은 `대기`(착수 가능) · `막힘-실기기`(사용자 기기 필요) · `막힘-사용자`(사용자 결정/조작 필요) 셋뿐.
