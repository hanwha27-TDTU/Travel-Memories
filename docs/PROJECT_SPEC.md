# PROJECT SPEC · Bugeon Journey

**최상위 제품·설계 기준.** 설계지시서(개인 여행기록 앱 통합 설계제안서 v0.1)를 저장소 SSOT로 반영한다. 충돌 시 이 문서가 이긴다. 세부는 각 도메인 문서(`DATA_MODEL`, `SECURITY`, `PRIVACY`, `SYNC_PROTOCOL`, `MEDIA_PIPELINE`, `ARCHITECTURE`) 참조.

## 1. 제품 비전

단순 여행일기가 아니라, 사진·장소·시간·비용·동행인·감정·회고를 서로 연결해 여행 당시의 기억과 의미를 **장기 보존**하는 개인 여행기록 데이터베이스.

> «사진, 장소, 비용과 짧은 감정을 자동으로 연결하여, 여행 당시의 기억과 여행이 나에게 남긴 의미를 다시 찾아주는 개인 여행기록 앱»

### 핵심 사용성 목표
| 목표 | 기준 |
|------|------|
| 여행 중 순간기록 | 사진 선택 제외 10초 이내 |
| 여행 후 회고 | 10분 이내 |
| 과거 여행 검색 | 3회 이내 조작 |
| 오프라인 기록 보존 | 내구성 로컬 커밋 후 앱 원인 유실 0건 (브라우저 축출·사이트데이터 삭제는 범위 밖) |
| 사진 일괄 처리 | 500장에서 강제종료 없이 대기열 |
| 업로드 장애 복구 | 실패 항목만 재시도 |
| 개인정보 | 모든 여행·사진 기본 비공개 |
| 데이터 이동성 | JSON·CSV·GeoJSON 내보내기 |

## 2. 핵심 설계 원칙
- **최소 입력** — 사진 선택 → 장소·날짜·시간 자동 확인 → 한 줄/음성 → 선택적 감정·비용 → 저장.
- **순간(Moment) 중심** — 여행을 긴 글 하나로 저장하지 않는다. `Trip→TripDay→Moment→Media/Place/Expense/Companion/Reflection`.
- **오프라인 우선** — 저장 시 IndexedDB에 먼저, 즉시 완료 표시, 이후 동기화(`SYNC_PROTOCOL`).
- **원본 불변** — 원본 사진 변경 없이 앱용 압축본 생성(`MEDIA_PIPELINE`).
- **개인자료 기본 비공개**(`PRIVACY`).
- **복구 가능성 우선** — 위험 작업은 사전검증·기록·재시도·되돌리기·결과확인.

## 3. 개발 범위

### MVP
계정(로그인·세션복구·로그아웃) · 여행(생성/수정/완료/보관/삭제) · 순간(빠른기록·메모·감정·중요기억) · 사진(다중선택·EXIF·압축·썸네일·업로드) · 타임라인 · 장소(지도·수정·중복통합) · 비용(금액·통화·분류·연결) · 회고 · 오프라인(로컬저장·대기열·복구) · 백업(JSON/CSV/GeoJSON) · 보안(RLS·비공개Storage·입력방어) · 운영(오류기록·용량표시·정리).

### MVP 범위 정련 (v0.2 · S-01~S-04)
- **S-01 음성입력**: MVP는 **OS 받아쓰기(dictation) 또는 audio note**로 한정한다. 앱 내 STT(음성→문자 엔진 내장)는 후속.
- **S-02 검색**: MVP는 **구조화·문자(키워드) 검색**만. **semantic(의미) 검색은 Phase 7**로 분리(2차의 "자연어 검색"은 Phase 7로 이동).
- **S-03 원본보관 모드**: **기본 비활성.** 원본 무손실 보관은 별도 bucket·TUS 재개 업로드·비용·restore gate를 갖춘 뒤에만 활성. **절약(압축본) 모드가 기본이며 이와 정합한다.**
- **S-04 회원가입/인증**: 개인 앱이므로 **공개 회원가입 비활성 / invite-only가 기본.** 소셜 로그인(Google 등)은 **소유자 계정 한정**으로만 사용한다.

### 2차
동행인 관리 · 통계 · OCR · 비용 자동추출 · 선택적 공유(제한시간 링크) · 영상. (자연어·의미 검색, AI 요약·태그, 로컬 LLM은 **Phase 7**로 이동 — §7·ROADMAP 참조.)

### 명시적 제외
공개 소셜 피드 · 팔로우/좋아요/댓글 · 예약/결제 · 지속 GPS 추적 · 몰래 위치수집 · 원본 전체 기본 클라우드 백업 · 자동 공개 여행기 · 경쟁형 점수/과도 배지 · 사용자 확인 없는 AI 기록 수정.

## 5. 핵심 사용자 흐름
- **여행 생성**: 제목·기간 → 국가·도시 → (선택)동행인·예산 → 로컬 저장 → 동기화 → 상세 진입.
- **순간 기록**: 사진/기록 시작 → 원본 기본정보 → 날짜·시각·장소 후보 → 짧은 메모 → 즉시 IndexedDB → 처리 대기열 → 압축본·썸네일 → 업로드 → 연결 확인.
- **여행 종료**: 완료 처리 → 누락 안내 → 대표사진 → 회고 → 요약 → 백업 권장 → 보관.

## 6. 비용 기록
분류: 숙박·교통·식사·카페·관광·쇼핑·통신·보험·의료·기타. 원 통화 금액 불변, 환율 환산은 보조값(환율 없어도 저장 가능). 상세 `DATA_MODEL`.

## 7. AI 원칙 (MVP 안정화 후)
AI는 기록 생성자가 아니라 정리 보조자다.
- 허용: 하루/여행 요약 초안, 사진 설명 초안, 태그 추천, 회고 질문 추천, 자연어 검색, 영수증 글자 추출, 비용 분류 추천.
- 금지: 실제 기록에 없는 사건 추가, 사용자 원문 덮어쓰기, 추정 장소를 확정 사실로 표시, 확인 안 된 사람 이름 생성, 비용 임의 수정, AI 결과를 사용자 작성글처럼 표시.
- 구조: `user_text, ai_output, ai_model, prompt_version, generated_at, source_record_ids, user_confirmed, user_edited`.

## 8. 성능·저장·접근성 (요약)
- 성능: 초기 화면 빠른 상호작용, 썸네일 지연 로딩, 압축은 Worker(UI 멈춤 없음), 디코딩·변환 동시 1·업로드 2(모바일, H-06), 타임라인 가상목록, 지도 마커 클러스터, 화면당 반복 요청 차단, Signed URL 최소 발급. **측정 후** 최적화(Performance Profiler).
- 저장용량: 설정에 파일 수·앱사진·썸네일·원본·영상·로컬대기·실패 용량 표시. 자동 정리는 임시파일·오래된 Signed URL 캐시·고아 검사. **사용자 확인 없이 서버 사진 자동 삭제 금지.**
- 접근성: 휴대전화 세로 우선, 터치 44px, 상태를 색상만으로 표현 안 함, 진행률 문자표시, 오류에 원인+해결행동, 키보드 탐색, 모달 초점 이동, 사진 설명 제공, 작은 회색 글씨 남용 금지, 지도 없이도 장소목록 사용 가능.

## 9. 최종 성공 기준 (§30)
여행 중 기록이 번거롭지 않다 · 내구성 로컬 커밋 후 앱 원인 유실 없음 · 원본은 기기에 유지 · 앱사진 자동 압축 · 수백 장 안전 대기열 · 실패 항목만 재시도 · 장소·사진·시간 자동 연결 · 과거 여행 쉽게 검색 · 의미 있는 회고 · 타 사용자 접근 불가 · 전체 데이터 내보내기·복원 · Claude Code와 Codex가 같은 문서·규칙 공유 · 모든 변경에 검사·인계 기록 · **저장소 자체가 최종 정보원**.
