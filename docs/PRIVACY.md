# PRIVACY · Bugeon Journey

설계지시서 §11.3·§13.2 + LESSONS §2. **개인자료 기본 비공개**가 제품 원칙이다.

## 기본 비공개

여행·사진·GPS·동행인·비용·회고는 **모두 비공개가 기본**이다. 사용자 승인 없이 소셜/공개 공유 기능을 추가하지 않는다. 공개 피드·팔로우·좋아요·댓글은 명시적 제외 범위(§3.3).

## 위치 정보

- 지속적인 위치 추적을 하지 않는다. **기록할 때만** 현재 위치를 요청한다.
- EXIF 위치는 사용자가 수정·삭제할 수 있다.
- 공유 파일에는 **기본적으로 위치정보 미포함**.
- 정확한 좌표 대신 대략적 위치로 바꾸는 기능을 제공한다.

## EXIF GPS/시각 = 민감 PII (핵심 계약 — 변경 전 문서집합 grep)

사진 EXIF는 GPS 좌표와 촬영시각을 담는다. 이를 **민감 PII로 취급**한다.
- 업로드 시 EXIF GPS 처리를 **확정**한다: **앱 내부 저장은 보존**, **공유·내보내기 산출물에서는 GPS 제거**(반올림 옵션 제공). 이 계약은 `check-exif-strip-on-share` 게이트로 강제하며, **사진 수집이 들어오는 Phase 3**에서 확인한다(Phase 4 아님).
- **EXIF whitelist (H-09)**: 원본 EXIF 전체 JSON을 저장하지 않는다. 허용된 필드만 `media_assets.exif_whitelist`에 담고 **MakerNote·기기 일련번호·얼굴영역·불필요한 전체 EXIF는 제외**한다. 게이트 후보 `check-exif-whitelist`. 상세 `docs/MEDIA_PIPELINE.md`·`docs/SECURITY.md`.
- 이 동작은 "나중에 반대로 바뀌기 쉬운" 침묵 동작 주장 부류이므로, 관련 코드를 바꾸기 전 문서집합에서 반대 주장이 없는지 grep한다(LESSONS §2, §7).

## 데이터 저장 경계

- 바이너리/개인 바이트는 **DB 행이나 브라우저 코드에 두지 않는다**. 사진 바이트는 Storage, 메타데이터는 Postgres, 캐시는 Dexie.
- 비공개 파일은 서버가 발급하는 짧은 만료 Signed URL로 접근.
- 로그·리포트에 토큰·Signed URL·위치 원문을 남기지 않는다.
- 파일명·경로에 사용자 이름·장소명·메모를 넣지 않는다(§10.2).

## 로그아웃·로컬 데이터 경계 (H-14)

- 로컬 행과 OPFS 경로는 `user_id`로 분리(user namespace)하고, 앱 시작 시 세션 사용자와 로컬 namespace 일치를 확인한다.
- 로그아웃 시 **"로컬 데이터 유지"와 "이 장치에서 삭제"를 명시적으로 구분**하고, 미동기화 자료가 있으면 삭제 전 경고한다. 로그아웃 즉시 이전 사용자 화면·캐시를 잠근다. 다른 계정 로그인 후 이전 자료를 표시하지 않는다.
- **로컬 데이터 보호 한계 명시**: MVP는 종단간 암호화를 약속하지 않는다. 잠금 해제된 기기나 동일 origin XSS에 대해 브라우저 로컬 저장(IndexedDB/OPFS)은 완전히 보호되지 않는다.

## AI와 개인정보

AI는 기록 생성자가 아니라 정리 보조자다. 사용자 원문을 덮어쓰지 않고, 추정 장소를 확정 사실로 표시하지 않으며, 확인되지 않은 사람 이름을 생성하지 않는다. AI 결과와 그 출처(`source_record_ids`)는 사용자 원문과 분리되어 `docs/DATA_MODEL.md`의 `ai_artifacts` 테이블(Phase 7)에 저장한다. 상세 원칙은 PROJECT_SPEC §15.

## 데이터 이동성 (사용자 권리)

전체 데이터를 JSON·CSV·GeoJSON으로 내보내고 복원할 수 있다. 사용자 확인 없이 서버 사진을 자동 삭제하지 않는다.
