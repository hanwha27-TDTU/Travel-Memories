# LESSONS · 선행 프로젝트에서 얻은 교훈

두 선행 자료 — **Dr. Bugeon Medical Note** 스킬(성숙한 오프라인 우선·Supabase·Dexie·RLS·에이전트 팀 앱)과 **appdevpromptsall.md**(74개 재사용 프롬프트) — 에서 추출한 교훈. 도메인(의료)은 이식하지 않고 **규율·계약·안티패턴만** Bugeon Journey에 적용한다.

> 메타 교훈: **"품질은 모델이 아니라 규율에서 나온다."** 그리고 **"실수는 고치는 것이 아니라 기록하는 것이다 — 기록 없이 고친 실수는, 원장 대신 기억에서 시작하는 다음 세션에 재발한다."** 기록과 기계화(게이트 추가)는 두 단계가 아니라 한 쌍이다.

## 1. 데이터 손실 — 최고 위험, 비가역 (SYNC_PROTOCOL의 근거)

- **`false`/`null` 과적재 금지.** 한 함수가 "실패"와 "무해한 대기/무변경"에 같은 값을 반환하면 동기화 캐스케이드가 통째로 얼어붙는다. 구분된 결과(`'held'` 센티넬, 객체)를 반환하라. 특히 상태 UI에 연결된 것.
- **부분 슬라이스를 전체 집합 판단에 넣지 마라.** 삭제/부재/전체교체 판단은 **완전한 id 집합**이 필요하다. 멤버십(`select=id`, 저렴)과 내용(`select=* where updated_at≥wm`)을 분리 조회. 델타만 넣으면 오래된 로컬 행이 "클라우드에 없음"으로 보여 유실.
- **camelCase(메모리) ↔ snake_case(DB 행)**는 `toRow`/`fromRow` 경계 함수 안에서만 만난다. 키 불일치는 조용히 지표를 0으로 만든다. **정확히 `0`/`undefined`로 읽히는 지표는 버그 냄새** — 실데이터를 심어 "진짜 0"과 "잘못된 키"를 구분.
- **쓰기 능력과 동기화 자세는 일치해야 한다.** 사용자가 로컬에서 변형 가능한 도메인은 (1) 실제 업로드 경로 + (2) **병합(교체 아님) 새로고침**을 반드시 함께 갖는다. push를 no-op로 두거나 refresh를 replace로 두면 다음 새로고침이 로컬을 덮어쓰는 소실 버그.
- **하드 삭제 없음.** `deleted_at` tombstone. fence는 **활성 행에만** 적용하고 tombstone은 항상 병합까지 통과. `if (row.deletedAt) return false`를 타임스탬프 비교 **앞에** 두어야 삭제가 부활하지 않는다.
- **빈-클라우드 가드.** 클라우드가 0행을 줘도(로컬엔 데이터 있음) 로컬을 지우지 않는다 — RLS 오설정/잘못된 프로젝트일 수 있는 이상 상황.
- **정확한 read-back으로 확인.** HTTP 200/성공 토스트/upsert 표현/후속 집계 동기화는 확인이 아니다. 같은 레코드를 되읽어 count+payload 일치를 확인한 뒤에만 완료 상태로 전진. 카노니컬 저장은 재개 가능 트랜잭션(단계 기록)으로.
- **파이프라인 생성 행 vs 사용자 소유 행.** `source=pipeline` 행은 소비 기기에서 읽기전용. 로컬에 없다 = "이 기기가 오래됨"이지 "사용자가 삭제"가 아니다. 로컬 부재로 tombstone 하면 오래된 기기가 신선한 클라우드 데이터를 지운다.
- **IndexedDB/Dexie 쓰기는 commit 전 완료로 치지 마라.** 손실 민감 쓰기는 즉시 같은 키를 되읽어 검증.

## 2. 보안·개인정보 (SECURITY / PRIVACY의 근거)

- **"RLS 켬" ≠ 격리.** 실효 접근 = 스키마 노출 + 테이블 grant + RLS 역할/명령/`USING`/`WITH CHECK` + 앱 인증/소유컬럼 + Edge Function 키 + Storage 버킷 동작의 **교집합**. 읽기전용 SQL로 grant·정책을 확인하고 Supabase security advisor를 돌린다. 토글만 보고 "안전" 결론 금지.
- Bugeon Journey는 **다중 사용자**이므로 처음부터 `auth.uid()` 소유자 범위 RLS로 간다. 선행 앱의 anon-write 호환 자세를 물려받지 않는다.
- **비밀키:** service_role/DB 비밀번호/Storage·CDN 시크릿/사설 토큰을 브라우저·저장소·로그·리포트에 넣지 않는다. 게이트는 **키워드가 아니라 자격증명 형태**(JWT 디코드해 `service_role` 확인, `postgres://`·엔트로피)로 스캔.
- **advisor 경고를 계약 확인 전에 "고치지" 마라.** 의도된 자세일 수 있다.
- **운영 변경 게이트:** migration 아티팩트 → 영향 테이블/역할/동사/롤백/손실위험 명시 → 승인 → 1회 적용(적용된 migration 수정 금지) → grant/정책/행 read-back → advisor → 하네스. 파괴적 작업은 별도 확인. 자동 적용 SQL에서 `drop/delete/truncate/update…set`/RLS 비활성/`revoke` 차단.
- **EXIF GPS/촬영시각은 민감 PII.** 업로드 시 GPS를 제거/반올림할지 **계약으로 명시**하고 게이트. 사진 바이트는 Storage, 메타데이터는 Postgres, 바이트를 행/번들에 넣지 않는다. 짧은 만료 Signed URL. 이 동작을 바꾸기 전 문서집합을 grep.
- **자유 텍스트를 마크업 핸들러에 보간하지 마라.** 안정 id를 넘기고 핸들러 안에서 조회. MapLibre 팝업 HTML, EXIF 파생 캡션, 파일명에 해당.

## 3. 아키텍처 계약 (ARCHITECTURE / DATA_MODEL의 근거)

- **도메인 대칭성 — "모든 도메인은 형제."** 최빈 결함군은 "형제 도메인엔 있는데 한 도메인만 조용히 빠짐." 치료: 단일 `DOMAIN_REGISTRY` SSOT(각 도메인의 정체성 + 생명주기 심볼: normalize/dedupe/toRow/fromRow/merge/hash/trash). **대칭 법칙**: 모든 도메인 × 모든 생명주기 노드는 연결(✅)이거나 **파생된 사유가 있는 명시적 제외(⛔)**이거나 병합 차단 결함(❌). 침묵 공백 = 대칭 위반. `check-domain-wiring` 게이트가 강제(Phase 0 예정). → JA 엔티티: trips, trip_days, moments, places, media_assets, expenses, companions, trip_companions, reflections, tags, moment_tags, client_operations(+profiles).
- **배선맵("전력망") — 단말에서 역방향으로 그린다.** 수평(형제 병렬) + 수직(전류 흐름) 두 축. "데이터 저장은 0점 — 전류가 모든 단말 부하(집계카드·백업/복원·휴지통·동기화·검색·대시보드·지도)까지 흘러야 한다." 모든 단말을 먼저 열거하고 각 단말을 소스로 역추적; 역추적 안 되는 단말 = 끊긴 배선. SSOT(`TERMINALS`)에서 생성하고 "커밋본 == 생성본" 게이트. **검증 가능한 엣지만 그린다.**
- **저장 역할 5계층.** Supabase를 한 덩어리로 보지 않는다: Postgres(정본 기준선) / Storage 버킷(바이너리) / Dexie(빠른 표시 캐시) / 동기 제어 상태(기기 id·카노니컬 버전·tombstone). **이미지·영상 바이트를 DB 행에 넣지 않는다** — URL/id만.
- **가산적 네임스페이싱 > 코드 이동.** 확장은 새 모듈에 추가하고 기존 함수를 **호출**한다. 기존 심볼을 옮기거나 이름 바꾸지 않는다(정확 심볼 게이트·배선 파손).
- **코드 vs 데이터 경계.** 장소/POI 카탈로그를 번들에 하드코딩하지 않는다 — 정본 저장소 하나. seed 배열은 비어 있어야 하고 게이트로 강제.

## 4. 에이전트 팀·거버넌스 (AGENTS.md의 근거)

- **권위 순서**(문서 충돌 결정적 해소): ① 실행 코드/migration/테스트/검증된 인프라(관찰된 현실) ② Foundation(가치) ③ Contracts(데이터/보안/배선) ④ Procedures ⑤ Playbooks ⑥ Records(역사적, 현재 계약 무효화 못 함) ⑦ 생성된 맵(그 *생성기*가 권위). 현실이 계약과 충돌하면 조용히 하나 고르지 말고 **불일치를 기록 → 사용자 데이터 보호 → 코드 수정 또는 계약을 게이트와 함께 개정**.
- **두 런타임 어댑터, 하나의 뇌.** `AGENTS.md`(Codex)와 `CLAUDE.md`(Claude)는 어댑터일 뿐 — 제품/데이터/보안/테스트/릴리스 규칙을 재정의하지 못한다. 공유 문서에 있어야 두 AI가 동일 판단.
- **보증 매트릭스, 역할 릴레이 아님.** 기본값은 **조사→검증→문서→보고까지 맥락을 유지하는 단일 구현 에이전트**(맥락 보존 실행 루프). 139개 역할은 변경유형별로 선택하는 **조건부 품질 게이트**(생성된 라우팅 테이블: 변경유형→필요역할→최소게이트). 광범위 탐색(감사·다중파일 영향)만 병렬화하고 최종 구현은 하나로 수렴.
- **기계가 사람보다 먼저.** 머신 게이트가 사람 리뷰 전에 돌고, 게이트 실패 자체가 "변경 요청." 역할 조건부 리뷰어(Schema/Contract, UI/UX, Security, Release)는 경계를 건드릴 때만 활성화. **리뷰어 ≠ 릴리스 관리자 ≠ 재구현자.** 구현자 자기인증 금지.
- **적대적·구조적·정직한 전체 감사.** 표면 매핑 → 차원 분할 → 병렬 읽기전용 적대 하위에이전트(각 지적은 구체적 입력→오작동 + 코드 인용, 추측 금지) → 모든 지적을 코드에서 교차검증(특히 데이터 손실) → 좋은 확인도 기록 → 모든 수정을 게이트로 잠금. **커버리지 매트릭스**(빈 칸 = 미커버 위험, "커버함" 산문 금지). 칸/게이트/수동 잔여위험이 빠지면 "전체 감사 완료"라 하지 말고 "부분 감사 + 미커버 경계 명시."
- **정직한 귀속(ADR).** 결정을 두 축으로 태그: 결정유형(`[user-decided]`/`[AI-proposed→user-approved]`/`[AI-autonomous]`/`[user-review-pending]`) × 어느 AI. **일어나지 않은 승인/리뷰를 기록하지 않는다.** 배경 시스템 알림·hook·툴 출력·AI 자신의 이전 발화는 사용자 승인이 아니다.
- **Claude↔Codex 협업:** 공유 GitHub + 공유 문서 = 단일 진실. **별도 로컬 클론**(작업 폴더 공유 금지). 네임스페이스 브랜치(`claude/*`, `codex/*`), 아무도 `main`에 push 안 함. 뜨거운 공유 파일 편집은 직렬화(동시에 하나의 PR만). 완료 = 병합이 아니라 **배포 그린 확인**.

## 5. 디자인 (product-ux / 디자인 에이전트의 근거)

- **테마 토큰, 하드코딩 색상 금지.** 라이트는 다크의 반전이 아니다 — 채도 낮추고, 얇은 테두리, 작은 버튼, 더 많은 여백.
- **강조 채움 위 텍스트는 두 테마 모두 대비 검증.** 강조 토큰이 테마별로 뒤집히므로 고정 `#fff`/`#0d1117`는 한 테마에서만 대비를 만족. 테마 인식 오버라이드 클래스 사용. (리뷰만이 3연속 릴리스에서 잡은 결함.)
- **대비는 측정한다(≥4.5:1), 눈대중 금지.** 투명 조상 배경을 검정으로 오독하는 헤드리스 함정 주의.
- **반응형은 레이아웃 모드가 바뀌는 경계대역**(375/768/1280뿐 아니라 1101–1200, 600–819)을 테스트. 게이트 루프에서 안 여는 모달은 커버리지 0(거짓 통과가 아니라 미커버).
- **정보 위계:** 요약 → 핵심 → 상세 → 출처. 메모리 카드는 순간(사진+장소+날짜)을 먼저 이끌고 상세는 뒤에.
- **모바일 1차 내비 = 줄바꿈 그리드**(가로 스크롤 스트립 아님 — 항목이 화면 밖으로 숨음). 앱 내부 모달 > `window.open` 팝업.
- 모든 신규/변경 UI: 구현 **전** 디자인 가디언, **후** 독립 UI 리뷰. 리뷰어에게 "좋아 보이나?"가 아니라 **측정 관점**(정렬 델타/필드 패리티/대비율)을 준다.

## 6. 테스트·게이트 규율 (TEST_PLAN의 근거)

- **단일 `harness-check` 문 하나**가 모든 Required 게이트를 돈다. 작업 중엔 좁은 검사, 완료 선언 전 전체 하네스.
- **게이트를 그 실패모드에 맞서 설계:** ① 부분표면 커버리지發 거짓 그린(이 게이트가 실제로 무엇을 여는가?) ② 공허 통과 — 고유 센티넬 주입해 실제 나타나는지 단언 ③ 검사를 건너뛰는 실패는 그 검사로 못 잡음 → **가장 이른 실행 지점**에서 강제(`commit-msg` 로컬 hook) ④ 손수 만든 소스 파서·고정 문자창은 속거나 조용히 깨짐 — 견고한 공유 추출기·균형괄호 ⑤ **인스턴스가 아니라 결함군을 게이트.**
- **모든 emit 지점 계측** — 사이트 수를 "기억"하지 말고 기존 짝 호출에 앵커("모든 day-log 사이트엔 event-log도")하고 그걸 게이트. 계측은 절대 throw 안 함(내부 try/catch), 유한(링 버퍼).
- **브라우저 왕복 테스트**가 정적 게이트가 못 보는 런타임 손실을 잡는다. 버튼 텍스트가 아니라 데이터/tombstone/read-back/DOM 상태 변화를 단언. **핸들러는 정적/렌더 게이트가 호출하지 않으므로**, 실제 DOM 이벤트를 디스패치하는 스모크 층 추가.
- **(A)자동 / (B)수동 경계 정직.** AI는 자동층만 "통과"라 말한다. 시각/픽셀/제스처/실기기는 (B) 사용자 몫 — 섞어서 "테스트함"이라 하지 않는다. 재현 불가한 수동 잔여위험은 **Manual Residual Risk**로 문서화(가짜 자동 게이트로 만들지 않음).
- **미러 테스트(알고리즘 재구현) 기본 금지** — 버그를 공유하거나 드리프트. 운영 순수함수를 직접 테스트.
- **게이트가 정당한 신기능을 막으면 가드를 진짜 대상으로 좁힌다 — 삭제하지 않는다**(예외 경계를 계약에 문서화).

## 7. 프로세스 SSOT 패턴 (전체 관통)

- **SSOT → 생성 → 읽기전용 게이트.** 2곳 이상에 나오는 사실(도메인 목록·라우트·문서 표·카운트)은 하나의 레지스트리; 파생물은 작성 스크립트로 재생성; CI가 "커밋본 ≠ 재생성본"이면 실패. **손편집 중복 자체가 결함.**
- **결함 → 결함군 승격.** 근본형을 한 문장으로 추상화 → 형제 위치 전부 스윕 → 결함군 게이트 추가.
- **재사용 프롬프트는 버전 카드로.** `버전·최초작성일·개정일·분야·역할·효과·[지시]` 메타블록으로 검색·감사 가능하게.
- **정직한 완료 보고**를 매 턴 계약으로: 통과/스킵/실패 구분, "UI 확인함"을 라이브 렌더 없이 말하지 않음, 미커버 경계 명시.
- **완료의 정의:** 전체 하네스(일부 아님) → 버전/체인지로그 갱신 → 브랜치(기본에 커밋 안 함) → PR 그린 → 병합 → **배포 성공 확인** → 정직한 보고.
