# TEST PLAN · Bugeon Journey

설계지시서 §23 + LESSONS §6. **단일 `harness` 문**이 게이트 전부를 돈다 — 정적·생성물 대조·유닛에 더해 **라이브 렌더(실제 브라우저)**까지 같은 명령에 들어 있다. 작업 중엔 좁은 검사, 완료 선언 전 전체 하네스.

> **라이브 층만 전제가 있다**(브라우저 + 최신 `dist`). 전제가 없으면 harness는 **통과가 아니라 「건너뜀」**으로 적고, 마지막 판정문이 "이번 실행은 그 층을 확인하지 않았습니다"라고 말한다. 전제를 갖춰 재려면 `npm run build && npm run live`, CI에서는 `live-render` job이 매 push마다 갖춰서 돌린다. 규율의 상세는 `gates-mechanization-dev` §2-G.

## 게이트 설계 규율 (실패모드 방어)

- **부분표면 커버리지發 거짓 그린 금지** — "이 게이트가 실제로 무엇을 여는가?" 새 화면/모달은 반응형·a11y 게이트 표면 목록에 추가되지 않으면 미커버(거짓 통과가 아니라 커버리지 0).
- **공허 통과 금지** — 고유 센티넬을 주입해 실제로 나타나는지 단언(매치=≥1, 무매치=0). 깨진 앱이 통과 못 하게.
- **가장 이른 실행 지점 강제** — 검사를 건너뛰는 실패(`[skip ci]` 류)는 CI가 아니라 `commit-msg` 로컬 hook으로.
- **견고한 공유 추출기** — 손수 만든 소스 파서·고정 문자창은 속거나 조용히 깨짐. 균형괄호·빈 캡처 시 명시적 실패.
- **인스턴스가 아니라 결함군을 게이트.**
- **(A)자동 / (B)수동 경계 정직** — AI는 자동층만 "통과". 시각·픽셀·제스처·실기기는 사용자 몫. 재현 불가 수동 잔여위험은 Manual Residual Risk로 문서화(가짜 자동 게이트 금지).
- **미러 테스트 기본 금지** — 운영 순수함수를 직접 테스트. 브라우저 왕복은 데이터/tombstone/read-back/DOM 상태 변화를 단언(버튼 텍스트 아님), 실제 DOM 이벤트 디스패치.

## 완료의 정의
전체 하네스(일부 아님) 통과 → 버전/CHANGELOG 갱신 → 브랜치(기본에 커밋 안 함) → PR 그린 → 병합 → **배포 성공 확인** → 정직한 보고. 자동검사 미통과 변경을 완료로 표시하지 않는다.
