# 지도·장소 개발 프롬프트 (Map & Place Dev Charter)

지도는 **장식이 아니라 공간적 기억을 되살리는 도구**다. 예뻐 보이려고 정보를 더하지 않는다.
타일 제공자 결정의 정본은 `docs/DECISIONS.md` ADR-0023이다.

## 1. 불변 계약

1. **외부 데이터는 신뢰 경계다**: Nominatim 결과는 남이 만든 문자열이다. **`textContent`로만** 렌더한다(`innerHTML` 절대 금지). 파싱은 형태를 검증하고 이상값은 버린다.
2. **좌표의 출처에 따라 수명이 다르다**:
   - **검색 좌표**는 이름과 묶여 있다 → 사용자가 이름을 손으로 고치면 **무효화**한다(다른 장소일 수 있으므로).
     단, 이미 안정 `placeId`로 연결된 편집은 장소 자체의 rename이므로 ID·좌표를 유지하고 연결된 이름을 함께 바꾼다(M-0124).
   - **지도에서 찍은 좌표**는 이름과 독립이다 → 이름을 나중에 적어도 **유지**한다(`mapPicked` 플래그).
   - 이 구분을 지우면 "지도로 찍고 이름 적었더니 위치가 사라짐" 결함이 돌아온다.
3. **등록되지 않은 장소를 지원한다**: Nominatim에 없는 곳도 기록할 수 있어야 한다 — 이름은 자유 입력, 좌표는 지도 탭으로. 검색 결과에 의존하는 흐름을 만들지 않는다.
4. **GPS는 민감 PII다**: 사진 EXIF GPS는 **서버에 동기화하지 않는다**(PRIVACY). 공유용 파생물에도 넣지 않는다. 지도 표시는 로컬 데이터로만.
5. **오프라인·실패 시 대체 경로**: 타일 로드 실패·WebGL 미지원이면 **장소 목록**으로 대체해 기억 접근을 보장한다. 지도가 안 떠도 앱이 막히면 안 된다.
6. **저트래픽 예의**: Nominatim은 공용 무료 서비스다 — 타이핑마다 자동 검색하지 않고 **버튼 제출 시에만** 호출한다. 귀속 표시를 유지한다.
7. **CSP는 같은 커밋에서**: 타일·지오코딩 호스트를 바꾸면 `index.html`과 `scripts/check-csp.mjs`의 `REQUIRED`를 함께 갱신한다(ADR-0023 규율).

## 2. 타일 제공자 (바꾸려면 이 조건 확인)

- 기본값: **OpenStreetMap 래스터** — 키·계정 불필요, 정적 배포 호환, 귀속 표시 필수.

### 🔴 사용자가 직접 좌표를 넣는 길을 **막지 않는다** (2026-07-30 사용자 제안)

> *"정 찾기 어려우면 네이버·카카오·구글에서 위치를 클릭해 좌표를 확인하고, 그 좌표를 장소
>   입력 필드에 붙여넣어 핀을 찍게 하면 어때?"*

지오코더 품질은 우리가 통제할 수 없다. **검색이 못 찾는 곳은 반드시 있다.** 그때 사용자가
쓸 수 있는 길이 없으면 그건 막다른 길이고, 이 앱에서 막다른 길은 곧 **기록되지 않은 기억**이다.

- **좌표 입력은 이름 검색보다 먼저 판정한다**(`parseCoordinateInput`). 지오코더에
  「37.587, 127.0016」을 물어봐야 좋은 답이 나올 리 없다.
- 🔴 **위·경도 순서는 원리적으로 모호할 수 있다.** 위도가 ±90을 넘을 수 없다는 제약이
  한국 좌표는 전부 풀어 주지만(경도>90), `41.9, 12.5`(로마)는 둘 다 위도일 수 있다.
  **모호하면 되묻는다** — 관례대로 적용하되 읽은 값을 화면에 적고 [↔ 바꾸기]를 준다(§8).
  조용히 추측하면 **기억이 엉뚱한 곳에 남고, 그건 조용하다.**
- **평범한 장소 이름은 반드시 파서가 거절해야 한다.** 「대학로」가 좌표로 오인되면 이름
  검색이 통째로 사라진다. 글자가 섞인 입력(「스타벅스 37.5, 127.0」)도 이름으로 본다.
- **왕복을 잠근다**: 앱이 내보낸 네 제공자 URL을 앱이 다시 읽어야 한다. 나가는 길만 있고
  돌아오는 길이 어긋나면 사용자는 방금 연 그 지점을 못 되찾는다.
- **역지오코딩은 거들어 주는 기능이다** — 실패해도 throw하지 않고, **비어 있을 때만** 채우며,
  **확정 시 1회만** 부른다(마커를 끌 때마다 부르지 않는다 — 공용 서버 예의).

### 🔴 구글 Maps API를 붙이지 않는 이유 (2026-07-30 검토 · ADR-0033 후속)

무료 한도는 충분하다(Geocoding = Essentials 월 10,000건). 저장도 가능하다 — 약관에
lat/lng/formatted_address **무기한 캐시** 예외가 있고 예시가 *"associating location data with
a photograph"*로 이 앱 그대로다. **막히는 곳은 표시다**:

> must not use Google Maps Content from the Geocoding API **in conjunction with a non-Google map**

이 앱은 MapLibre+OSM에 핀을 찍으므로 정면 위반이다. 구글 지도로 갈아타면 **오프라인이 죽고**
(§1 5항), 아이러니하게 **한국 지도 품질이 나빠지며**(국외반출 제한), 키 없는 정적 배포
전제(ADR-0023)가 깨진다. → **API 대신 좌표 붙여넣기**로 같은 목적을 약관 문제 없이 이룬다.
(딥링크 「구글 지도에서 열기」는 API가 아니라 링크라 약관 대상이 아니다 — 그건 유지한다.)

### 지오코더는 하나로 고정하지 않는다 (2026-07-30 · 사용자: 한국+해외 둘 다)

- **Nominatim은 언제나 마지막에 있다** — 키가 필요 없으므로 시크릿 0에서도 앱이 돈다.
  국내 제공자(카카오·VWorld)는 **개선이지 전제가 아니다.**
- 한글이 섞이거나 좌표가 한국 안이면 국내 제공자 먼저. **해외 질의에는 국내 제공자를 아예
  부르지 않는다**(답 없을 걸 알면서 부르지 않는다).
- 키가 필요한 제공자는 **반드시 Edge Function 뒤**(§0). 검색어는 로그에 찍지 않는다 —
  어디를 찾아봤는지가 곧 어디에 갔는지다(원칙 #3).
- 🔴 **정밀도는 앱이 다시 판정한다.** 서버가 보낸 등급을 믿지 않는다 — 등급 규칙이 한 벌이어야
  제공자들이 **같은 자**로 재진다(§7 2층).
- 🔴 **「더 정확하다」는 재고 말한다**: `npm run compare:geocoders`(응답률·정밀도 분포·제공자 간
  1순위 거리). 승자를 정하지 않는다. 외부 호스트가 막힌 환경에서는 **SKIP(exit 2)**이다.
- `VITE_MAP_STYLE_URL`로 교체 가능(사용자 자신의 MapTiler/Stadia 등). 교체 시 CSP 호스트도 함께.
- **정직**: OSM 타일 사용정책은 대량 트래픽 앱을 권장하지 않는다 — 개인·저트래픽이라 수용하되, 규모가 커지면 전용 제공자로 옮긴다.
- 인라인 래스터 스타일을 쓰므로 스타일 JSON 외부 fetch가 없다(글리프·스프라이트 없음). 벡터로 바꾸면 이 전제가 깨지니 CSP를 재점검.

## 3. 과거 결함 등록부

| 사례 | 근본형 | 재발 방지 |
|---|---|---|
| 🔴 연결된 순간에서 이름을 고치자 placeId·좌표가 사라져 대장에서 못 찾는 고아가 됨(M-0124) | 편집 폼이 표시값만 복원하고 관계의 안정 ID는 초기화함 | 편집 상태에 기존 placeId를 의무 전달하고, 연결 rename은 장소·모든 연결 순간·op을 한 트랜잭션에서 미러한다. 이름-only 고아는 추측 연결하지 않고 대장에 복구 경로를 노출한다 |
| 🔴 서로 다른 앱 저장소가 같은 과거 장소 20쌍을 별도 UUID로 소급 등록(M-0123) | 한 Dexie 트랜잭션의 중복 방지 사정권을 기기 간 유일성까지 확장해 해석 | 미연결 정리는 active+trash 직접 순간 0개를 서비스 트랜잭션에서 재검사해 tombstone한다. 기기 간 자동 생성에는 결정적 ID나 서버 원자 upsert 같은 **분산 정체성 계약**이 따로 필요하다고 명시한다 |
| 장소 선택 후 결과창이 안 사라짐 | `display`를 가진 클래스가 `[hidden]` 속성을 이김 | 전역 `[hidden]{display:none!important}` — **결함군으로 박멸**(UI 헌장 §3과 공유) |
| 지도로 좌표를 찍고 이름을 적으면 좌표가 사라짐 | 좌표 무효화 규칙을 출처 구분 없이 적용 | `mapPicked` 플래그로 지도 좌표는 이름과 독립 유지 |
| (예방) 검색 결과를 `innerHTML`로 렌더할 뻔 | 외부 문자열을 신뢰 | `textContent` 전용 + CSP 게이트 |
| (예방) 지도 팝업이 재렌더 때 엉뚱한 순간을 가리킴 | 팝업을 배열 인덱스로 식별 | **안정 id**로 식별(인덱스 금지) |
| 🔴 지점이 **하나**일 때 지도가 광역으로 남음(M-0050) | 확대수준 규율을 두 곳에 손으로 구현해 한쪽만 빠짐(§7) | 출처를 `zoomForSpan()` **한 곳**으로 + 라이브가 **실제 요청된 타일 z**를 잰다 |
| 🔴 도(道) 중심점과 건물 출입구를 **같은 문장**으로 말함(M-0050) | 파서가 `place_rank`·`boundingbox`를 버려 정밀도를 **모르면서 아는 척**(§8) | `domain/place/precision.ts`(순수) — 등급·범위·글리프. 점이 아니면 지도 미세조정을 권한다 |
| 🔴 라이브러리에서 **다시** 고르면 등급을 말하지 않음 | 같은 사실을 앱이 두 번 다르게 말함(§7 사용자 대면 대칭) | `verdictFromStored()` — 저장해 둔 등급을 그대로 다시 말한다 |
| 🔴 라이브 검사가 `nth(1)`로 결과를 골라 조용히 엉뚱한 줄을 잼 | **검사 쪽의 인덱스 식별** — 위 팝업 결함과 같은 근본형이 검사에서 재발 | 라이브는 **이름(hasText)으로** 고른다 |
| (예방) 붙여넣은 좌표의 위·경도를 뒤집어 읽을 뻔 | 두 값이 모두 ±90 안이면 **값만 보고는 순서를 알 수 없다** | 모호하면 `ambiguous: true`로 밝히고 화면이 되묻는다 + [↔ 바꾸기] |
| (예방) 얀덱스 링크만 `ll=경도,위도`인 것을 놓칠 뻔 | 넷 중 하나만 반대인 비대칭 | 파서가 제공자별로 나눠 읽고, 왕복 유닛이 네 URL을 전부 잠근다 |
| 🔴 좌표 입력칸이 화면 3분의 1을 먹는 덩어리가 됨(2026-08-05 육안) | `flex: 1 1 200px`을 **가로 flex용으로 쓴 값**을 세로 flex 부모 안 형제에 그대로 물려줌 → 200px이 **높이**가 됨 | 축이 다른 부모에는 같은 flex 값을 주지 않는다. `.sync-note`에서 이미 한 번 난 형태(§3-E) |
| (예방) 대장 검색이 5건에서 잘려 여섯 번째 장소가 **없는 것과 같아질 뻔** | 조용한 절단은 「전부 봤다」로 읽힌다(§5 3항) — 자동완성에서 「외 N건 생략」은 읽히지 않는다 | 상한을 아예 두지 않는다. 검색·정렬을 `domain/place/registry.ts` **한 곳**에 두어 대장과 순간 편집이 같은 답을 준다 |

| 🔴 결과 상자에 그리는 손이 둘인데 **먼저 시작한 쪽이 나중에 끝나** 남의 결과를 지움(M-0105) | `await` 뒤에 그리는 두 경로가 「나중에 그린 쪽이 이긴다」는 **시간**에 기댐. 시간은 계약이 아니다 | `ResultsOwner`: 그리려면 `claim()`으로 주인이 되고 `await` 뒤 `holds()`로 확인. 세 번째 손도 같은 문을 지난다(§7 2층). **전체 하네스가 기존 라이브 검사에서 잡았다**(`element was detached`) |

## 📍 위치관리대장 — 좌표 순서는 **저장이 아니라 화면**으로 푼다 (v1.77 · 2026-08-05)

사용자 요청은 *"좌표 2개 버전으로 관리(위도와경도의 순서를 바꾸는 경우도 있으므로)"*였다.
논의 끝에 **한 벌 저장 + 두 벌 보기**로 정했다(사용자 결정).

### 왜 두 벌을 저장하지 않는가

두 벌을 저장하면 **어느 쪽이 정본인지 앱이 모른다.** 지도·통계·내보내기가 매번 골라야 하고,
고르는 규칙이 없으면 조용히 한쪽을 쓴다 — **그게 M-0057에서 기억이 기니만 앞바다에 찍힌
방식이다.** 모호함을 데이터에 남기면 그 모호함은 언젠가 조용히 해소된다(잘못된 쪽으로).

### 대신 화면이 답을 드러낸다

```
지금 이것 → 41.3111, 69.2797      우즈베키스탄 · 타슈켄트
뒤집으면  → 69.2797, 41.3111  [↔ 이걸로 바꾸기]   (바다 · 주소 없음)
```

물리 제약이 대부분을 가른다 — **위도는 ±90을 넘을 수 없다.** 한국 좌표(경도 124~132)는
뒤집으면 불가능하므로 `ambiguous: false`이고, 이때는 **뒤집기를 권하지 않는다.**
🔴 「있어야 할 때 있는가」만 재면 절반이다 — **「없어야 할 때 없는가」**를 함께 재라(§4).
늘 뒤집기를 권하면 그건 오탐이고, 오탐은 빡빡한 게 아니라 **틀린 것**이다(§7-D).

### 대장은 이미 있었다 — 없었던 것은 화면이다

`LocalPlace` 테이블이 이름·주소·국가·도시·좌표를 다 갖고 있었고 `savePlace()`가 장소를 만들
때마다 넣고 있었다. **스키마 변경 0.** 새 기능을 만들기 전에 *"이미 쌓이고 있지 않은가"*를
먼저 물어라 — 이 저장소는 데이터가 있는데 창이 없는 경우가 여러 번 있었다
(「기기별 현황」도 같은 형태로 접힌 출처에 묻혀 있었다).

### 역지오코딩은 좌표를 밖으로 보낸다

국가·도시 자동 입력은 **좌표 한 쌍이 Nominatim으로 나간다**(사용자가 2026-08-05에 명시적으로
승인). 나가지 않는 것: 이름·메모·사진·여행 제목. 화면이 그 사실을 말하고 `docs/PRIVACY.md`에
같은 내용을 적는다. 저트래픽 예의(§1 6항)대로 **장소 하나당 필요할 때 1회**만 부른다 —
목록을 그릴 때마다 전수로 부르지 않는다.

🔴 **지오코더가 준 것은 주소일 뿐, 이름이 아니다.** 사용자가 「집」이라 적은 곳을
`Yunusobod tumani`로 덮으면 안 된다(§1 3항 — 지오코더에 없는 곳도 담아야 한다).

## 바깥 지도 칩 줄은 **`ui/externalMapRow` 한 곳**이다 (2026-07-30)

사용자 제안으로 장소 검색 실패 자리에도 칩을 붙이면서 뽑았다. 그 전에는 열기 로직이
`mapView.ts` 안에 **인라인**이었다.

> **복사하지 마라.** 이 부품이 들고 있는 것은 UI가 아니라 **개인정보 동의 절차**다 —
> 제공자별 1회 확인 · 거절하면 열지 않음 · `noreferrer`로 앱 주소 안 새기 ·
> 좌표로 집은 것과 이름으로 찾은 것을 **같은 문장으로 말하지 않기**(`caveat`).
> 두 곳에 손으로 구현하면 한쪽이 낡을 때 **조용히 새어 나간다**(§7 2층).

**새 자리에 칩을 붙일 때**

```ts
const row = externalMapRow({ name, lat, lng }, { lead: '다른 지도에서 찾기', className: '...' });
if (row) container.appendChild(row);   // 열 곳이 없으면 null — 빈 줄을 만들지 않는다
```

- **좌표를 모르는 자리면 `lat/lng: null`을 넘긴다.** 그러면 `precision: 'name'`이 되고
  *"같은 이름이 여러 곳이면 다른 곳이 열릴 수 있어요"*가 **자동으로** 붙는다. 좌표가 없는데
  있는 척하면 앱이 엉뚱한 곳을 그 장소라고 우기는 셈이다(§8).
- **제공자를 골라 넣지 마라.** 등록부(`PROVIDERS`)가 정한 넷이 전부 나간다 — 안내 문장이
  셋만 말하고 있던 것이 실제 결함이었다(§7: 형제 하나가 조용히 빠지지 않게).
- `data-ext-map="<id>"`가 붙어 있다 — 라이브 검사가 **어느 제공자인지 알고 누를 수 있게**(§13 4항).

## 사진 위치로 장소를 채울 때 (v1.28 · 2026-07-31)

사용자 제안: *"장소도 사진 입력하면 사진정보에서 우선 가져오도록 하면 어떨까요?"* — 맞았고,
**부품이 이미 다 있었다**(`readPhotoMeta`가 GPS를 읽고 지도 화면이 그걸로 마커를 찍고 있었다).
순간을 만드는 화면만 그걸 안 쓰고 사용자에게 다시 치게 했다(§12).

### 🔴 좌표와 이름은 **개인정보 등급이 다르다**

| 무엇 | 네트워크 | 동의 |
|---|---|---|
| 사진 GPS로 **좌표 채우기** | **0** — 기기 밖으로 안 나간다 | 필요 없다(물을 것이 없다) |
| 그 좌표로 **이름 찾기**(역지오코딩) | 좌표가 Nominatim으로 나간다 | 🔴 **처음 한 번 확인**(`PHOTO_GEO_CONSENT_KEY`) |

**왜 이름 검색과 다르게 묻나**: 이름 검색은 사용자가 치고 [검색]을 누른 것이라 의도가 분명하다.
사진 GPS는 **사진을 골랐을 뿐인데** 위치가 나간다 — 묻지 않으면 모르는 사이에 나간다(원칙 #3).
거절해도 **좌표는 남긴다.** 기능을 통째로 막지 않는다.

동의의 저장·판정은 `services/consent.ts` **한 곳**이다(`externalMapConsent`도 거기를 지난다).
새 「밖으로 나가는 자리」를 만들면 그 파일에 키와 문구를 추가한다 — 손으로 두 벌 구현하지 않는다.

### 규율

- **사용자가 손댄 것을 덮지 않는다.** 이름을 적었거나 좌표를 이미 골랐으면 아무 일도 없다.
- 🔴 **「없다」를 먼저 처리한다.** 위치 있는 사진 → 없는 사진으로 바꿨을 때 *먼저 고른 사진의*
  좌표를 말하는 문장이 남으면 화면이 거짓말을 한다(M-0021의 형태). 실제로 그렇게 짰다가
  라이브 게이트에 잡혔다 — `taken()` 검사보다 `!hint.coord` 검사가 **앞**이다.
- **여러 장이면 가장 이른 촬영시각의 사진**(아래 별도 절). 평균 좌표는 **아무도 서 있지 않은
  지점**이라 값을 지어내는 것이다.
- **근거를 말한다**: 「📷 사진 위치에서 · 위도, 경도 (3장 중 가장 이른 사진)」.

### 🔴 좌표를 **못 얻었을 때가 더 중요하다** (v1.31 · M-0054 · 2026-07-31)

> 이 자리에 *"좌표 없는 사진은 **침묵**(§8)"* 이라고 적혀 있었다. **그게 결함이었고, 문서가
> 그 결함을 정당화하고 있었다.** 같은 증상이 v1.30·v1.31 **두 판을 살아남았다.**

- **§8의 「침묵이 정상」을 반대로 쓰지 마라.** 그 조항이 감추라는 것은 *기대와 일치하는 것*이지,
  **사용자가 기대한 일이 안 일어난 것**이 아니다. 사진을 골랐는데 장소가 안 채워진 것은
  정상이 아니라 **설명이 필요한 사건**이다. 침묵하면 사용자는 **고장으로 읽는다.**
- **문장은 `photoPlaceNotice(hint)` 한 곳에서 만든다.** 사진→장소 경로는 **둘**이고
  (①순간 만들기 폼 ②기존 순간에 사진 추가), v1.30이 ②에만 인라인 문자열로 붙였다가
  ①이 계속 침묵했다. 새 경로를 만들면 **이 함수를 부른다** — 문자열을 새로 적지 않는다.
- **원인을 구분해 말한다.** 원인이 다르면 사용자가 할 일이 다르다:
  - `timedCount > 0` → 시각은 읽혔다 = **파서는 멀쩡하다.** 「촬영시각은 읽었는데 위치 정보가
    없어요 — 안드로이드 사진 선택기가 위치를 지웠을 수 있어요」
  - `timedCount === 0` → EXIF 자체가 없다(스크린샷·메신저로 받은 사진)
- **탈출구를 함께 준다** — 지도로 찍기·좌표 붙여넣기(둘 다 v1.25에 이미 있다). 「안 됩니다」로
  끝내지 않는다(§12).
- **이미 장소가 있으면 침묵한다.** 그때는 앱이 못 한 일이 없다. 단 **낡은 문장은 지운다**(M-0052 ①).

## 📷 사진은 **원본 보존 경로가 기본이다** (v1.40 · 2026-08-01 · M-0064)

> 🔴 **이 절은 v1.34에서 정반대였다.** 그때는 기본이 갤러리 선택기였고 「📁 원본에서」가
> 우회 버튼이었다. **그 배치의 대가를 사용자가 나흘 치렀다** — 자세한 전말과 계약은

**사실**: 갤러리 상세 화면이 그 사진의 위치를 지도로 보여준다 → **파일 안에 GPS가 있다.**
지우는 것은 안드로이드 **사진 선택기**다. *"EXIF가 없다"*가 아니라
*"사진 선택기를 거치면 없어진다"*가 정확한 문장이다.

- **기본 `accept`는 `ORIGINAL_ACCEPT`**(사진 아닌 형식을 하나 섞어 **파일 선택기**로 내려감).
  갤러리는 **[🖼️ 갤러리에서]로 명시적으로 고를 때만.** 되돌리지 마라 —
  `check-exif-order`의 검사 D와 `verify-editor-live`가 둘 다 막는다.
- **부품은 `ui/pickOriginal.ts` 하나.** `wireAltPick(input, btn, accept)`.
- 🔴 **입력칸을 새로 만들지 마라.** 하나를 두 방식으로 여는 것뿐이다 — 고른 뒤의 처리
  (미리보기·EXIF·압축·저장)가 기존 경로를 그대로 지나야 한다(§7 2층).
- 🔴 **`accept`를 되돌려라.** 고른 경우(`change`)와 **취소한 경우**(`focus`) 둘 다.
  되돌리는 자리가 이제 **원본 보존 쪽**이다 — 안 되돌리면 다음 [사진 추가]가 위치를 잃는다.
- 🔴 **「내가 재보지 못했다」는 기본값을 안 바꿀 이유가 된다. 사용자가 재준 뒤에는 아니다.**
  v1.34의 *"안 통해도 잃는 것이 없게 별도 버튼으로 둔다"*는 신중해 보였지만, **기본 경로가
  계속 깨져 있는 값**을 계산에 넣지 않았다. 우회로를 만든 것은 **고친 것이 아니다.**

## 📍 「지금 내 위치」 (v1.33 · 2026-07-31)

사용자: *"장소가 바로 입력되게 하고 싶은거야. 어떤 방식이든 결과가 중요함."* + *"무료지도 자체가
위치가 정확하지 않아서 GPS 도움 받으려는거거든"*

- **문 하나**: `services/here.ts`(브라우저 호출) + `domain/place/here.ts`(판정·문장). 새 자리에
  붙일 때 `navigator.geolocation`을 직접 부르지 마라 — 실패 처리·타임아웃 보호가 거기 있다.
- 🔴 **정확도 등급을 새로 만들지 마라.** `hereVerdict(accuracyM)`가 GPS 반지름을 ×2 해서
  기존 `precisionFromSpan`에 넣는다. 그래야 「⚠ 동네 범위」 같은 한정 문장이 검색·지도와
  **같은 어휘로** 나온다(§7 사용자 대면 대칭). 실내 wifi 측위는 실제로 2km로 온다.
- 🔴 **자동으로 넣지 않는다.** 「지금 여기」는 「그때 거기」가 아니다 — 소급 입력에서 자동으로
  넣으면 어제의 기억이 오늘 집 주소에 찍히고, **그 오류는 조용하다**(원칙 #1·§8).
  누르는 것은 *"여기가 맞다"*는 사용자의 판단이다. 앱이 할 일은 **누르기 쉽게 만드는 것**.
- **숫자 좌표를 화면에 남긴다** — 사용자가 옮겨 적고 다른 지도앱과 대조할 수 있어야 한다(§12).
  「위치 지정됨」만 적는 것은 이 사용자의 목적(정확한 좌표 확보)에 아무 도움이 안 된다.
- **실패 사유 넷을 뭉개지 마라**(`denied`·`unavailable`·`timeout`·`unsupported`).
  권한을 켜야 할 사람과 잠시 기다리면 될 사람이 **정반대 행동**을 해야 한다.
- **라이브로 재는 법**: `context.grantPermissions(['geolocation'], { origin })` +
  `setGeolocation(...)`으로 **실제로 눌러** 본다(§13 4항). 실패 경로는 권한을 지우지 말고
  `getCurrentPosition` **하나만** 갈아 끼운다 — 헤드리스에서 권한을 지우면 콜백이 안 와
  검사가 빈손으로 지나가고, **늦게 도착한 결과가 뒤 블록 화면을 덮는다**(실측).

### 🔴 플랫폼 사실 — 안드로이드가 GPS를 지운다 (없는 버그를 찾지 않도록)

**안드로이드 13+의 사진 선택기가 GPS EXIF를 지우는 사례가 보고돼 있다** — 🔴 **늘 그런 것은 아니다**(2026-07-31 실기기: 사후 업로드에서 좌표가 그대로 들어왔다 · M-0056). 위치가 없을 때 **원인을 이것 하나로 단정하지 마라**.
개인정보 보호 설계이고 `ACCESS_MEDIA_LOCATION` 권한과도 **무관하게** 지운다. 브라우저가 받는
바이트에 이미 위치가 없으므로 **`media/exif.ts`를 아무리 고쳐도 못 읽는다.**

- 촬영시각(`DateTimeOriginal`)은 **살아남는다** — 그래서 「시각은 있는데 좌표만 없다」가
  이 경우의 지문이다.
- 미확인 우회: 갤러리 대신 **「파일」 앱(문서 선택기)** 으로 고르면 원본 바이트가 온다고 알려져
  있다. **이 저장소는 실기기 검증을 못 했다** — 버튼으로 만들기 전에 실기기에서 먼저 확인할 것
  (§13 3항: 못 봤으면 못 봤다고 적는다).

## 사진에서 여행 시간대를 제안할 때

좌표→시간대는 경계 데이터셋(수 MB)이 필요해 **하지 않는다.** 대신 이미 하고 있는 역지오코딩이
**나라 코드**를 주고, 나라→시간대는 `Intl`이 안다(`domain/time.ts`의 `zonesForCountry` — 0바이트).

- 🔴 **시간대가 하나인 나라일 때만 제안한다.** 여럿이면(미국 29개·우즈베키스탄 2개) **침묵**한다 —
  조용히 하나를 집으면 §8이 금지하는 반올림이고, 엉뚱한 시간대는 **Day 묶음까지 흔든다**.
- **자동으로 정하지 않는다.** 묻고, 버튼 하나로 적용한다(§12 — 말하고 끝내지 않는다).
- **이미 정해진 시간대는 덮지 않는다.**
- ⚠️ **id는 브라우저가 정한다.** Chromium에서 `zonesForCountry('VN')`은 `Asia/Ho_Chi_Minh`이 아니라
  별칭 `Asia/Saigon`을 준다. 그래서 시간대 `<select>`에 `ensureOption`이 있다 — 목록에 없는
  값(별칭·옛 기록)이 **조용히 「미지정」으로 바뀌지 않게**. 검사에서 특정 id를 고를 때도
  목록에 있는지 먼저 확인하라(`Asia/Ho_Chi_Minh`으로 `selectOption`했다가 타임아웃 났다).
- `Intl.supportedValuesOf('timeZone')`은 418개인데 **`UTC`는 그 안에 없다.** 기기 시간대가
  목록 밖이면 한 번 바꾼 뒤 되돌아갈 길이 사라진다 — 그래서 집 시간대 칸은
  `alsoOffer: [deviceZone()]`로 「내 기기 시간대」를 늘 남긴다.

### 🔴 폼 칸을 채울 것인가, 데이터를 쓸 것인가 (v1.29 · 2026-07-31)

**저장 시점이 다르면 같은 해법이 안 통한다.**

| 흐름 | 사진을 넣으면 | 그래서 |
|---|---|---|
| 순간 **생성** 폼 | 폼에 머문다([저장]을 눌러야 저장) | **폼 칸을 채운다**(사용자가 보고 고칠 수 있다) |
| 「사진 추가」(**편집**) | 곧바로 저장하고 재렌더 | **데이터를 쓴다**(폼 칸은 그 즉시 사라진다) |

데이터를 쓰는 쪽은 조건이 더 무겁다:

- **비어 있을 때만.** 이름이든 좌표든 하나라도 있으면 손대지 않는다.
- **말하고 되돌릴 길을 준다**(`showUndoToast`). 앱이 사용자 데이터를 스스로 바꿨으면 §5다.
  진행 줄·폼 안내로는 안 된다 — **재렌더가 지운다.** 토스트는 `document.body`에 붙어 살아남는다.
- 동의는 **이미 있을 때만** 쓴다. 사진 굽는 중에 대화상자를 띄우면 흐름이 끊긴다.

### 여러 장 중 **대표 사진**은 「가장 이른 촬영시각」

시각(`guessOccurredAt`)이 그 규칙을 쓰므로 장소도 같아야 한다. 다르면 **시각과 장소가 서로
다른 사진을 가리키고**, 그 어긋남은 사용자에게 보이지 않는다(§7 사용자 대면 대칭).
촬영시각을 아는 사진이 없을 때만 고른 순서를 쓴다.
