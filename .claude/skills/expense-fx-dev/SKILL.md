# 비용·환율 개발 프롬프트 (Expense & FX Dev Charter)

이 문서는 비용·환율 기능을 만들며 실제로 밟은 실수와 그로부터 굳힌 규칙의 집대성이다.
여기 규칙과 코드가 어긋나면 **코드가 진실**이고, 이 문서를 갱신한다(SSOT 규율).
상위 원칙은 `CLAUDE.md`(원금액 불변·정직한 완료·사용자 기록과 AI/기계 생성물 분리)와 `docs/DATA_MODEL.md`를 따른다.

## 1. 불변 계약 (어기면 데이터/신뢰 손상)

1. **원금액 불변(H-04)**: `originalAmount`(>0)·`originalCurrency`는 사용자가 적은 값이다. **어떤 환산·정규화도 이 두 필드를 덮어쓰지 않는다.** 환산은 표시 시점에 파생할 뿐 저장하지 않는다.
2. **사용자 기록 ≠ 기계 파생(원칙 #2)**: 환산값은 **시각적으로 구분**한다(`.chip-approx` — 옅게·구분선·`≈` 접두). 사용자가 적은 금액이 주(主), 환산이 부(副).
3. **환율 기준일 = 비용이 발생한 날(사용일)**: 순간의 `occurredAt`을 `localDate()`로 **로컬 달력 날짜**로 변환해 쓴다. 입력한 날(`createdAt`)이 아니다.
   - **ISO 문자열을 잘라(`slice`) 날짜를 만들지 않는다** — 그건 UTC 날짜이지 사용자의 날짜가 아니다(§4 M-utc-slice). `check-timezone` 게이트가 강제한다.
   - 미래 날짜는 존재하지 않으므로 `fxDateFor`가 오늘로 당긴다.
4. **과거 환율은 확정값**: 지난 날짜의 기준환율은 안 바뀐다 → 캐시는 **영구 유효**, 오늘 날짜 표만 TTL(현재 6h) 후 갱신. 이 성질 덕에 "그때 얼마였지"의 답이 볼 때마다 달라지지 않는다.
5. **만들 수 없으면 `null`**: 환율이 없으면 0이나 추정치로 얼버무리지 않고 환산 표시를 **생략**한다. 특히 **과거 환율 조회 실패 시 오늘 환율로 대체하지 않는다**(틀린 숫자를 그럴듯하게 보여주는 것보다 안 보여주는 게 낫다).
6. **심볼 위조 금지**: 깔끔한 통화 심볼이 없으면(AED·CHF·EGP·SAR) 만들어내지 말고 **코드를 표시**한다(`1,000.00 AED`).
7. **환율 없이 다른 통화를 더하지 않는다**: `sumByCurrency`는 통화별로 분리한다. 환산 합계를 낼 때도 환산 못 한 통화는 **숨기지 말고** 라벨에 남긴다(`환산 합계 (XXX 제외)`).
8. **환율 캐시(`localFxRates`)는 파생 데이터**: 재취득 가능한 공개 데이터이지 사용자의 기억이 아니다 → 동기화·백업 대상이 아니며 `check-backup-coverage`·`check-blueprint` EXCLUDE에 **근거 주석과 함께** 등록한다.
   - ⚠ 새 테이블을 EXCLUDE에 넣기 전 자문: **"이걸 잃으면 사용자의 기억이 사라지나?"** 그렇다면 제외 금지.
9. **환율은 앱을 막지 않는다**: 보조 정보이므로 네트워크 실패·오프라인이어도 예외를 던지지 않고 조용히 환산만 생략한다(기록·표시는 정상).

## 2. 정직한 표시 규칙 (과장 금지)

- **"실시간 환율"이라 쓰지 않는다.** 공개된 **기준환율**이며, 카드 결제·현찰 환전 시 수수료 때문에 실제 금액과 다르다 — 화면에 명시한다.
- **근거를 감추지 않는다**: 환산 배지를 탭하면 **적용 환율일·단위환율(양방향)·계산식·출처**가 보인다. 사용자가 계산기로 검산할 수 있어야 한다.
- **요청일과 적용일이 다르면 이유를 밝힌다**: 주말·공휴일엔 고시가 없으므로 직전 고시일이 쓰인다 → `2026-07-24 (사용일 2026-07-25은 고시 없음 → 직전 고시일)`.
- **개인정보**: 환율 조회 때 나가는 것은 **통화코드와 날짜뿐**이다. 금액·장소·기록을 전송하지 않는다(이 성질을 깨는 제공자로 바꾸지 말 것).

## 3. 제공자 선택 근거 (바꾸려면 이 조건부터 확인)

| 순위 | 제공자 | 근거 |
|---|---|---|
| 주 | `@fawazahmed0/currency-api` | 200+ 통화(**UZS 포함**), 날짜 고정 URL로 과거 환율, API 키·호출제한 없음, CC0. jsDelivr → `*.currency-api.pages.dev` 예비 |
| 보조 | Frankfurter | ECB 기준이라 주요 ~30개 통화 품질은 높으나 **UZS가 없을 가능성이 크다**(ECB가 솜을 고시하지 않음) |

- **필수 조건**: 사용자가 우즈베키스탄 거주 → **UZS 지원은 타협 불가**. 제공자를 바꾸려면 UZS + 과거 날짜 조회를 먼저 확인한다.
- 새 제공자를 붙이면 **CSP 호스트를 `index.html`과 `scripts/check-csp.mjs`의 `REQUIRED`에 같은 커밋으로** 추가한다(ADR-0023 규율). 안 하면 게이트가 그 의존을 보증하지 못한다.
- API 키가 필요한 제공자로 바꾼다면 키를 프론트에 두지 말 것(§0 비타협). Edge Function 경유 + `check-secret-leak`에 형태 패턴 추가.
- 응답은 **대문자 키·유한 양수만** 남겨 정규화한다(신뢰 경계 — 외부 데이터를 그대로 믿지 않는다).

## 5. 검증 체크리스트 (정직한 완료)

자동층(전부 통과해야 "통과"라 말한다):
1. `npm run typecheck` · `npm test` · `npm run harness`(12게이트) · `npm run build`
2. 순수 로직은 **고정 픽스처로 유닛테스트**(현재 `tests/unit/fx.test.ts` + `expenseFormat.test.ts` = 42건). 비공허: 알려진 실패를 주입해 RED 확인.
3. 통화를 추가하면 유닛이 자동으로 지켜준다(국기 전수 검사·코드 유일성·상단 5개 순서). 이 성질을 깨지 말 것.
4. **시간대**: 날짜가 얽힌 변경은 `check-timezone`이 UTC 아닌 두 시간대에서 유닛을 재실행한다. 로컬에서 직접 확인하려면 `TZ=Asia/Seoul npx vitest run`.

라이브 렌더(`node scripts/verify-editor-live.mjs`):
- 환율 기준통화 설정 렌더·국기·선택 **read-back**(성공 토스트가 아니라 실제 저장값 확인)
- 환산 배지 렌더 → 탭 → 상세(적용일·양방향 환율·계산식·출처) → 재탭 접힘
- **콘솔 에러 0** — 이 환경은 환율 API가 차단돼 있으므로, 에러 0이 곧 "네트워크 실패 시 무해하게 degrade한다"의 실증이다.

**샌드박스의 정직한 경계**: 이 환경은 환율 API 호스트를 네트워크 정책으로 차단한다(`curl`·`WebFetch` 모두 403). 그래서
- UI 경로는 **Dexie `localFxRates`에 픽스처를 직접 주입**해 검증한다(네트워크 검증이 아님을 명시할 것).
- 실제 응답·UZS 지원·과거 날짜 범위는 **실기기 확인 몫**이다. "확인했다"고 말하지 말 것.
